# GitSpace — 설계 문서 (Design Spec)

- **작성일:** 2026-07-15
- **상태:** V1 설계 확정 (구현 계획 대기)
- **한 줄 정의:** 로컬 git 저장소의 브랜치·커밋·머지를 3D 우주 항성계로 시각화하는, 예술 우선(aesthetic-first) 데스크톱 뷰어.

---

## 1. 목적 & 정체성

- **1차 정체성:** "살아있는 예술 · 우주감." 아름다움·몰입감이 최우선. 기능(정보·액션)은 그 위에 얹는다.
- **동기:** GitHub 네이티브 대시보드/Insights와 상용 팀 분석 도구가 "기능적 대시보드"는 이미 잘 채우고 있다. 아무도 채우지 않은 빈틈은 **git 활동을 하나의 살아있는 우주로 감상하는 경험**이다. (선행 조사: `2026-07-15 prior-art 리서치` 참조.)
- **감상 방식:** 화면 모서리의 **타임 스크러버**를 밀면 시간이 흐르고, 그에 따라 별(브랜치)들이 태어나고·이동하고·병합되는 것을 지켜본다. idle 시 자동 회전 = 스크린세이버.

## 2. 핵심 컨셉 & 은유 (확정)

| git | 우주 |
|---|---|
| 저장소 | 하나의 항성계 (장면 전체) |
| 기본 브랜치(main) | 중심 태양·핵 |
| 브랜치 | 빛나는 별 (궤도를 도는 몸체, HEAD가 선두 별) |
| 커밋 | 궤도 위 마디(작은 점) |
| 머지 | 두 궤도가 한 밝은 별로 수렴 |
| 작성자 | 별 색 (팀 협업 = 여러 색 별이 한 계에 공존) |
| 시간 | 모서리 스크러버로 진행 → 별 생성·이동·병합 |
| 태그/릴리스 | 초신성 섬광 (V1 옵션) |

**두 가지 설계 원칙**
1. **위치는 의미를 갖는다** — 별·마디의 배치는 **실제 git DAG 순서·부모관계**를 반영한다(임의 배치가 아니다).
2. **연출은 몰입을 위한 것** — 궤도·성운·발광(bloom)은 아름다움을 위한 표현 계층이다.

> 이 하이브리드는 "겉모습 = 궤도 성좌(A안) / 속 배치 = 진짜 git DAG(B안)"의 결합이다.

## 3. 범위 (Scope)

### V1 (이번 스펙)
- ✅ 로컬 **단일 저장소** 1개를 항성계로 렌더
- ✅ 브랜치 = 별, 커밋 = 궤도 마디, 머지 = 수렴, 작성자 = 색
- ✅ 타임 스크러버(스크럽 + 자동 재생/일시정지·속도)
- ✅ photoreal 렌더(스타필드·블룸·성운)
- ✅ 기본 상호작용(궤도 회전·줌·hover 정보)
- ✅ 오프라인·인증 불필요 (로컬 git만)

### 명시적 제외 (YAGNI → V2+)
- ❌ PR·이슈·CI·리뷰 (GitHub API 연동)
- ❌ 멀티 저장소 / 은하(galaxy) 계층 뷰
- ❌ 계정 로그인·팀 API (V1의 "팀"은 **로컬 커밋 작성자 색**으로만 표현)
- ❌ git 쓰기 작업(커밋·브랜치 편집) — **읽기 전용 뷰어**

## 4. 아키텍처

```
① 로컬 git 저장소 (.git)
        │  (디스크 읽기)
        ▼
② Rust 백엔드 (Tauri core) 🦀
     ├─ git 리더 (gitoxide / git2): DAG·브랜치·작성자·타임스탬프 파싱 → 원시 커밋 그래프
     └─ 레이아웃 변환기 (순수 함수) ⭐: git DAG → SceneModel  ← TDD 핵심
        │  (SceneModel JSON, Tauri IPC command/event — 단방향)
        ▼
③ WebView 프론트 (React + react-three-fiber / Three.js)
     ├─ 씬 렌더러: 별·궤도·성운·블룸(HDR postprocessing)
     ├─ 타임 스크러버: 모서리 UI → 현재 시각 t 상태
     └─ 상호작용: hover 정보 · 궤도 회전 · 줌 · (옵션) 클릭 상세
```

**핵심 경계**
- Rust는 **읽기·변환만** 담당. 그림은 전부 프론트.
- 둘 사이는 **SceneModel(JSON) 단방향 계약**.
- 스크러버의 시간 `t`는 **프론트 상태**. SceneModel을 한 번 받아두고, "t에 무엇을 보일지"는 프론트가 결정 → 재조회 최소화, 스크럽이 부드럽다.
- 네트워크·인증·DB 없음. git 실행 파일 의존 없이 **라이브러리로 파싱**.

## 5. 데이터 모델 — SceneModel 계약 (초안)

Rust 변환기가 출력하고 프론트가 소비하는 JSON. 좌표는 백엔드에서 계산해 넘긴다(프론트는 렌더만).

```jsonc
SceneModel {
  repo:     { name, path, defaultBranch },
  timeline: { start: <unix>, end: <unix> },      // 스크러버 범위
  authors:  [ { id, name, email, color } ],       // 색 배정 포함
  branches: [ Star ],
  commits:  [ CommitNode ],
  merges:   [ MergeEvent ],
  meta:     { totalCommits, sampled: bool, droppedCount }  // 절단 알림용
}

Star (branch) {
  id, name, isDefault: bool, authorId?,
  orbit: { radius, inclination, phase },          // 궤도 형상(연출 파라미터)
  headCommitId, bornAt: <unix>
}

CommitNode {
  id: <sha>, branchId, parentIds: [<sha>...],
  authorId, timestamp: <unix>, message,
  position: { x, y, z },                          // DAG 순서 반영해 계산된 좌표
  orbitT                                          // 궤도 상의 진행값(0..1)
}

MergeEvent { commitId, intoBranchId, fromBranchId, timestamp: <unix> }
```

## 6. git → 우주 좌표 매핑 (레이아웃 알고리즘)

변환기(순수 함수)의 책임. 개략:

1. **위상 정렬(topological sort)** 후, 각 커밋을 소속 **브랜치(레인)**에 배정 (first-parent 우선).
2. **시간 파라미터**: 커밋 타임스탬프(기본) 또는 위상 인덱스를 진행값으로 사용 → 타임라인 축.
3. **궤도 배정**: 기본 브랜치는 가장 안쪽/중심. 다른 브랜치는 겹치지 않도록 서로 다른 궤도(반지름·경사)를 부여 (분기 깊이·생성 순서 기반).
4. **커밋 배치**: 각 브랜치의 커밋을 시간순으로 그 브랜치 궤도 위에 마디로 배치.
5. **머지 처리**: 부모가 2개 이상인 커밋에서, 유입 브랜치 궤도를 대상 위치로 수렴시키고 **밝은 머지 별**을 만든다.
6. **스크럽 시간 t**: 프론트가 `timestamp ≤ t`인 요소만 표시, 별을 t 시점 위치로 보간, t가 머지 시각을 지날 때 합류 애니메이션 재생.

## 7. 타임 스크러버 & 상호작용

- **타임 스크러버:** 화면 모서리 진행바. 드래그로 스크럽, 자동 재생/일시정지, 속도 조절. 범위 = `timeline.start..end`.
- **카메라:** 궤도 회전(orbit control)·줌. idle 시 자동 회전(스크린세이버 모드).
- **Hover:** 별 → 브랜치 이름·작성자 / 커밋 마디 → 메시지·sha·날짜 (가벼운 툴팁).
- **저장소 열기:** 로컬 폴더 선택 다이얼로그.
- **클릭 상세:** 옵션(가벼운 패널). V1 필수 아님.

## 8. 렌더링 / 비주얼

- 다크 스타필드 배경, 별 = 발광 구체 + **블룸(HDR postprocessing)**, 궤도 = 반투명 라인, 성운 = 소프트 글로우.
- 색 = 작성자. (옵션) 밝기·크기 = 활동량.
- 머지 = 합류 애니메이션. 태그/릴리스 = 초신성 섬광(옵션).
- **목표 인상:** 첨부된 다중성계 레퍼런스 이미지 수준의 photoreal.

## 9. 에러 처리 & 엣지케이스

| 상황 | 처리 |
|---|---|
| git 저장소 아님 | 명확한 안내 후 폴더 재선택 유도 |
| 빈 저장소(커밋 0) | 빈 우주 + 안내 메시지 |
| 단일 브랜치 / detached HEAD | 정상 처리 |
| orphan 브랜치(공통 조상 없음) | 별도 항성계 조각으로 분리 렌더 |
| 매우 큰 저장소(수만 커밋) | 상한·샘플링 + **사용자 알림**(조용한 절단 금지), 오래된 커밋 LOD(뭉치기·페이드) |
| 손상/접근불가 .git | 명확한 에러 메시지 |

## 10. 테스트 전략

- **변환 계층(순수 함수) = TDD 핵심:** 합성 git 그래프 픽스처 → 기대 SceneModel(위상·타임라인·머지)을 단위 테스트 (`cargo test`). 렌더링과 분리돼 있으므로 결정적(deterministic) 테스트 가능.
- **git 리더:** 소형 테스트 저장소 픽스처로 통합 테스트 (분기·머지·orphan 케이스 포함).
- **렌더러:** 자동화 어려움 → 수동/스냅샷(썸네일) 확인.
- **E2E 스모크:** Tauri에서 샘플 repo 열기 → 장면 생성까지.

## 11. 기술 스택

- **셸:** Tauri (Electron 대비 경량·Rust 네이티브)
- **백엔드:** Rust + gitoxide(또는 git2)
- **프론트:** React + react-three-fiber(Three.js) + postprocessing(bloom)
- **변환 계층:** 순수 Rust 함수(렌더 무관), 단위 테스트 대상

## 12. 향후 로드맵 (V2+)

- GitHub API 연동: PR·이슈·CI를 우주 요소로(예: PR = 형성 중인 궤도/성간 다리, CI 상태 = 별 건강/색, 이슈 = 소행성대).
- 멀티 저장소 → 은하 계층(줌아웃 = 여러 항성계).
- 팀/조직 계정 로그인 기반 협업 뷰.
- 역사 replay 영상 내보내기(공유용).

## 13. 열린 질문 (구현 계획에서 확정)

- 시간 파라미터 기본값: 커밋 타임스탬프 vs 위상 인덱스 (타임스탬프는 리베이스/왜곡에 취약).
- 궤도 배정의 구체 규칙(겹침 방지 휴리스틱).
- 대형 저장소 커밋 상한 기본값·샘플링 방식.
- gitoxide vs git2 최종 선택(기능·성숙도 검토).
